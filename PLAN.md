# Maintenance plan

0xKern3lCrush is maintained in small, focused commits. One change a day.

This is a working plan, not a contract.

## Week 1

- Mon - plain ASCII pass across the repository
- Tue - README rewrite in the standard layout
- Wed - contributing guide
- Thu - maintenance plan
- Fri - issue and pull request templates
- Sat - rename the repository to 0xKern3lCrush
- Sun - references pass

## Week 2

- Mon - detection notes for driver load and IOCTL
- Tue - blocklist status snapshot
- Wed - artifacts and hashes review
- Thu - mitigation notes pass
- Fri - documentation pass
- Sat - sources check
- Sun - README pass

## Week 3

- Mon - add a third case study
- Tue - driver comparison table
- Wed - safe reconnaissance walkthrough
- Thu - limitations pass
- Fri - continuous integration
- Sat - release checklist
- Sun - changelog pass

## Week 4

- Mon - tag the release
- Tue - announce
- Wed - review open questions
- Thu - final review
- Fri - README pass
- Sat - sources check
- Sun - plan the next case

## Commit conventions

- one change per commit, present tense
- subject under 72 characters, no trailing period
- no working exploit code

## Daily checklist

1. Pick the next item.
2. Make the smallest change that completes it.
3. Commit with a plain message.
4. Push to main.
